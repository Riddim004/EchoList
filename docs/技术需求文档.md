## 1. 项目概述

### 1.1 项目背景

开发一款专为 Android 平台设计的智能任务管理应用。用户通过**语音或文字**描述任务，应用借助 AI 大模型（GLM-4.7-Flash，免费版）自动完成**语义理解、时间提取、任务分类**，并在指定时间**触发提醒通知**。

### 1.2 平台选择

- **仅支持 Android 原生开发**：规避 Apple 生态的审核门槛与开发复杂度。
- 技术栈采用 Kotlin + Jetpack 全家桶，保证长期可维护性。

### 1.3 产品目标

| 目标 | 衡量指标 |
| --- | --- |
| 自然语言创建任务 | 单句输入 → 结构化任务成功率 ≥ 90% |
| 时间解析准确 | 常见中文时间表达（明天下午三点、周五早上等）解析准确率 ≥ 95% |
| 提醒可靠触发 | 提醒触发误差 ≤ 1 分钟，杀后台仍可触发 |
| 端到端响应 | 从输入确认到任务落库 ≤ 3 秒（网络正常时） |

## 2. 功能规格说明

### 2.1 功能清单

| 编号 | 功能模块 | 优先级 | 说明 |
| --- | --- | --- | --- |
| F1 | 语音识别输入 | P0 | 语音转文字，作为任务描述来源 |
| F2 | 文字输入 | P0 | 标准文本框输入任务描述 |
| F3 | AI 语义理解 | P0 | 调用 GLM-4.7-Flash 提取时间/事件/类别 |
| F4 | 智能分类 | P0 | 自动归类为「工作」/「生活」 |
| F5 | 时间提取与解析 | P0 | 相对时间、绝对时间、模糊时间解析 |
| F6 | 智能提醒 | P0 | 精确闹钟 + 通知，支持重启恢复 |
| F7 | 任务列表管理 | P0 | 查看、编辑、完成、删除任务 |
| F8 | 离线降级 | P1 | 无网络时基于规则的本地时间解析 |
| F9 | 任务确认卡片 | P1 | AI 解析结果展示给用户确认/修正后再落库 |
| F10 | 历史与统计 | P2 | 已完成任务归档、按类别统计 |

### 2.2 F1 语音识别输入

**功能描述**：用户点击麦克风按钮，说出任务内容（如"明天下午三点开产品评审会"），应用将语音转为文字并进入 AI 解析流程。

**技术方案**：
- 首选 Android 原生 `SpeechRecognizer`（`RecognizerIntent.ACTION_RECOGNIZE_SPEECH`），免费、无需额外 SDK。
- 语言设定 `zh-CN`，开启 `EXTRA_PARTIAL_RESULTS` 实时显示识别中间结果。
- 设备不支持时（`SpeechRecognizer.isRecognitionAvailable() == false`）降级为纯文字输入并提示用户。

**交互要求**：
- 录音过程中显示声波动画与实时转写文字。
- 识别结束后文字回填输入框，用户可修改后再提交。
- 识别失败（超时/无声音/网络错误）给出明确 Toast 提示并允许重试。

**权限**：`RECORD_AUDIO`（运行时动态申请，拒绝后展示引导说明）。

### 2.3 F2 文字输入

- 主界面底部常驻输入栏：文本框 + 麦克风按钮 + 发送按钮。
- 支持多行输入，最长 500 字符。
- 发送后输入内容以"用户消息"形式展示（类聊天流交互），AI 解析结果以"卡片"形式回复。

### 2.4 F3 AI 语义理解（核心）

**功能描述**：将自然语言任务描述发送至 GLM-4.7-Flash，通过 **Function Calling（工具调用）** 方式让模型输出结构化结果。

**模型选择**：
- 主模型：`glm-4.7-flash`（智谱 AI 当前免费模型，混合思考模型；旧 glm-4-flash 系列请求已被平台自动路由至此），请求时显式开启思考模式（`thinking: {"type": "enabled"}`）提升时间换算与多任务拆分准确性
- API 端点：`https://open.bigmodel.cn/api/paas/v4/chat/completions`
- 认证：`Authorization: Bearer <API_KEY>`
- 参数：`temperature=0.1`（追求确定性输出）、`tool_choice="auto"`

**提取字段**：

| 字段 | 类型 | 说明 | 示例 |
| --- | --- | --- | --- |
| title | string | 任务标题（精炼后的事件内容） | 产品评审会 |
| category | enum | WORK / LIFE | WORK |
| remindTime | string (ISO 8601) | 提醒时间，无法确定则为 null | 2026-07-28T15:00:00+08:00 |
| timeExpression | string | 原始时间表达（用于用户核对） | 明天下午三点 |
| note | string | 补充信息 | - |

**Prompt 约束**：
- System Prompt 中注入**当前日期时间与时区**（相对时间解析的基准）。
- 明确分类标准：工作 = 会议/汇报/项目/客户/加班等；生活 = 购物/家务/就医/社交/健身等；模糊时按语境倾向判断，默认 LIFE。
- 时间只出现日期无时刻时使用默认时刻（上午 9:00）；"晚上"默认 20:00、"下午"默认 15:00、"早上"默认 8:00。

### 2.5 F4 智能分类

- 分类由 GLM-4.7-Flash 在工具调用参数中直接输出（枚举约束 `["WORK", "LIFE"]`）。
- 用户可在确认卡片或任务详情中手动改类，手动修改的优先级最高。
- UI 上以颜色区分：工作（蓝色系）、生活（绿色系）。

### 2.6 F5 时间提取与解析

**支持的时间表达类型**：

| 类型 | 示例 | 解析结果 |
| --- | --- | --- |
| 绝对时间 | 7月30日上午10点 | 2026-07-30T10:00 |
| 相对日期 | 明天 / 后天 / 下周三 | 基于当前日期偏移 |
| 相对时段 | 半小时后 / 两小时后 | 当前时间 + 偏移 |
| 模糊时段 | 明晚 / 周五早上 | 日期 + 默认时刻 |
| 无时间 | 记得买牛奶 | remindTime = null，仅存任务不设提醒 |

**双通道解析策略**：
1. **主通道**：GLM-4.7-Flash 语义解析（在线）。
2. **降级通道**：本地规则引擎（正则 + 关键词映射），覆盖"明天/后天/X点/X小时后"等高频表达，供离线场景使用（F8）。

**校验规则**：
- 解析出的时间早于当前时间且在 24h 内 → 视为次日同刻，并在确认卡片中高亮提示。
- 解析出的时间早于当前时间超过 24h → 判为解析异常，提示用户手动选择时间。

### 2.7 F6 智能提醒系统

**技术方案**：
- 使用 `AlarmManager.setExactAndAllowWhileIdle()` 设置精确闹钟（Doze 模式下仍可触发）。
- Android 12+ 需要 `SCHEDULE_EXACT_ALARM` 权限；Android 14+ 使用 `USE_EXACT_ALARM` 或引导用户授予精确闹钟特殊权限，被拒时降级 `setWindow()`（窗口 10 分钟）。
- 闹钟触发 → `BroadcastReceiver` → 发送高优先级通知（`NotificationChannel`，IMPORTANCE_HIGH，带声音与震动）。
- 通知动作按钮：**完成**、**稍后提醒（+10 分钟）**。
- 注册 `BOOT_COMPLETED` 接收器，设备重启后从数据库恢复所有未触发的闹钟。

**可靠性要求**：
- 所有待提醒任务持久化在 Room 数据库，闹钟仅作触发器，不作为唯一事实来源。
- 应用启动时执行一次"闹钟对账"：遍历未完成且未过期的任务，重新注册缺失的闹钟。

**权限**：`POST_NOTIFICATIONS`（Android 13+ 运行时申请）、`SCHEDULE_EXACT_ALARM`、`RECEIVE_BOOT_COMPLETED`。

### 2.8 F7 任务列表管理

- 首页 Tab：**全部 / 工作 / 生活 / 已完成**。
- 任务卡片显示：标题、类别标签、提醒时间、剩余倒计时。
- 操作：滑动完成、滑动删除（带撤销 Snackbar）、点击进入详情编辑（标题/时间/类别）。
- 编辑提醒时间后自动取消旧闹钟并注册新闹钟。

## 3. 系统架构设计

### 3.1 总体架构（Agent 系统架构模式）

```
┌─────────────────────────────────────────────────────────┐
│                     Presentation 层                       │
│   ChatInputScreen / TaskListScreen / TaskDetailScreen    │
│              (Jetpack Compose + ViewModel)               │
└──────────────────────────┬──────────────────────────────┘
                           │ UiState / Intent
┌──────────────────────────▼──────────────────────────────┐
│                      Agent 层（核心）                     │
│  ┌────────────┐  ┌──────────────┐  ┌──────────────────┐   │
│  │ TaskAgent  │→│ LlmClient     │→│ GLM-4.7-Flash API │   │
│  │ (编排器)   │  │ (Retrofit)   │  └──────────────────┘   │
│  └─────┬──────┘  └──────────────┘                       │
│        │ tool_calls                                     │
│  ┌─────▼──────────────────────────────────┐             │
│  │      ToolCallingHarness（工具调用框架）  │             │
│  │  ToolRegistry / ToolExecutor / Schema  │             │
│  └─────┬──────────────────────────────────┘             │
│        │ dispatch                                       │
│  ┌─────▼──────────────────────────────────────────┐     │
│  │ 预定义工具集 (Tools)                            │     │
│  │ create_task / set_reminder / classify_fallback │     │
│  │ parse_time_local / query_tasks                 │     │
│  └─────┬──────────────────────────────────────────┘     │
└────────┼────────────────────────────────────────────────┘
         │
┌────────▼────────────────────────────────────────────────┐
│                       Domain / Data 层                    │
│  TaskRepository │ ReminderScheduler │ Room DB │ DataStore │
└──────────────────────────────────────────────────────────┘
         │
┌────────▼────────────────────────────────────────────────┐
│                      System 层                            │
│  AlarmManager │ NotificationManager │ SpeechRecognizer   │
│  BroadcastReceiver (Alarm / Boot)                        │
└──────────────────────────────────────────────────────────┘
```

### 3.2 Agent 工作流

```
用户输入（语音→STT→文字 / 直接文字）
   │
   ▼
TaskAgent.process(userText)
   │  1. 组装消息：System Prompt（含当前时间、分类规则）+ 用户输入
   │  2. 附带 tools 定义（JSON Schema）
   ▼
GLM-4.7-Flash /chat/completions
   │  返回 tool_calls: create_task({...})
   ▼
ToolCallingHarness
   │  3. 校验参数（Schema 验证 + 时间合法性校验）
   │  4. 路由到 CreateTaskTool
   ▼
CreateTaskTool.execute()
   │  5. 生成 TaskDraft → UI 展示确认卡片（F9）
   ▼
用户确认
   │  6. TaskRepository.insert() 落库
   │  7. ReminderScheduler.schedule() 注册精确闹钟
   ▼
到点触发 AlarmReceiver → 通知提醒
```

**多轮工具调用**：Harness 支持将工具执行结果以 `role=tool` 消息回传模型，形成"模型→工具→模型"循环（最大 3 轮，防止死循环），用于处理"帮我看看明天有什么安排，然后加个会"这类复合指令。

### 3.3 Tool Calling Harness 设计

**核心接口**：

```kotlin
interface AgentTool {
    val name: String                    // 工具名，与 API tools 定义一致
    val description: String            // 供模型理解的功能描述
    val parametersSchema: JsonObject   // JSON Schema 参数定义
    suspend fun execute(args: JsonObject): ToolResult
}

class ToolRegistry {
    fun register(tool: AgentTool)
    fun toApiToolsJson(): List<ToolDefinition>  // 转 GLM API tools 字段
    fun dispatch(toolCall: ToolCall): ToolResult // 校验 + 路由 + 执行
}

sealed class ToolResult {
    data class Success(val data: JsonObject) : ToolResult()
    data class Failure(val error: String) : ToolResult()  // 回传模型自纠错
}
```

**设计要点**：
- 工具注册制：新增能力只需实现 `AgentTool` 并注册，Harness 与业务解耦。
- 参数强校验：模型输出的 JSON 先经 Schema 验证，非法参数以 `Failure` 回传模型重试一次，仍失败则走人工确认兜底。
- 全链路日志：每次 tool_call 的入参/出参/耗时记录到本地日志，便于调优 Prompt。

### 3.4 预定义工具集

| 工具名 | 功能 | 关键参数 |
| --- | --- | --- |
| `create_task` | 创建结构化任务（主工具） | title, category, remind_time, time_expression, note |
| `set_reminder` | 为已有任务单独设置/修改提醒 | task_id, remind_time |
| `query_tasks` | 查询任务（支持按类别/日期过滤） | category?, date_range? |
| `complete_task` | 标记任务完成 | task_id |
| `parse_time_local` | 本地规则时间解析（离线降级用，不暴露给模型） | text, base_time |

### 3.5 GLM-4.7-Flash 接口规格

**请求示例**：

```json
{
  "model": "glm-4.7-flash",
  "thinking": {"type": "enabled"},
  "temperature": 0.1,
  "messages": [
    {"role": "system", "content": "你是任务管理助手。当前时间：2026-07-27T14:30:00+08:00（周一）。从用户输入中提取任务并调用 create_task 工具。分类规则：……"},
    {"role": "user", "content": "明天下午三点开产品评审会"}
  ],
  "tools": [{
    "type": "function",
    "function": {
      "name": "create_task",
      "description": "根据用户描述创建一个任务",
      "parameters": {
        "type": "object",
        "properties": {
          "title": {"type": "string", "description": "精炼的任务标题"},
          "category": {"type": "string", "enum": ["WORK", "LIFE"]},
          "remind_time": {"type": "string", "description": "ISO8601 提醒时间，无法确定填 null"},
          "time_expression": {"type": "string", "description": "原文中的时间表达"},
          "note": {"type": "string"}
        },
        "required": ["title", "category"]
      }
    }
  }],
  "tool_choice": "auto"
}
```

**异常处理**：

| 场景 | 策略 |
| --- | --- |
| 网络超时（>10s） | 重试 1 次 → 失败则走本地规则解析（F8）+ 提示 |
| 429 限流 | 指数退避重试（1s/2s），提示"AI 繁忙" |
| 模型未返回 tool_call（闲聊输入） | 将模型文本回复直接展示（轻量对话能力） |
| tool_call 参数非法 | Failure 回传模型自纠错 1 次 → 兜底人工表单 |

**API Key 管理**：Key 存于 `local.properties`（不入版本库），通过 BuildConfig 注入；发布版本建议接入自有中转服务避免 Key 泄露。

## 4. 数据设计

### 4.1 Room 实体

```kotlin
@Entity(tableName = "tasks")
data class TaskEntity(
    @PrimaryKey(autoGenerate = true) val id: Long = 0,
    val title: String,
    val category: String,        // WORK / LIFE
    val remindTimeMillis: Long?, // null = 无提醒
    val timeExpression: String?, // 原始时间表达
    val note: String?,
    val rawInput: String,        // 用户原始输入（语音转写/文字）
    val status: String,          // PENDING / DONE / EXPIRED
    val createdAt: Long,
    val updatedAt: Long
)
```

### 4.2 数据流

- 单一事实来源：Room 数据库；UI 通过 `Flow<List<Task>>` 响应式订阅。
- 用户偏好（默认提醒时刻、通知开关）存 `DataStore<Preferences>`。
- 所有数据仅存本地，不上传云端（发送给 GLM 的仅为单条任务文本）。

## 7. 关键风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| GLM 免费额度限流/策略变化 | 解析不可用 | 本地规则解析降级通道；LlmClient 接口化便于换模型 |
| 厂商 ROM 杀后台导致提醒失效 | 核心体验受损 | 精确闹钟 + 开机恢复 + 首次启动引导用户加白名单 |
| 时间解析歧义（"下周三"跨周语义） | 提醒时间错误 | 确认卡片强制用户核对时间；System Prompt 注入完整日期上下文 |
| 原生语音识别在部分设备不可用 | 语音功能缺失 | 检测可用性并降级文字输入；后续可选接入第三方 STT |
| 模型输出参数不合法 | 任务创建失败 | Schema 校验 + 自纠错回传 + 人工表单兜底 |

## 9. 验收标准（摘要）

1. 语音输入"明天下午三点开产品评审会" → 生成任务：标题=产品评审会、类别=工作、提醒时间=次日 15:00，并在该时刻收到通知。
2. 文字输入"周六记得买牛奶" → 类别=生活，提醒时间=本周六 09:00（默认时刻）。
3. 输入"记得给妈妈打电话"（无时间） → 任务创建成功、无提醒、类别=生活。
4. 断网状态输入"两小时后取快递" → 本地规则解析成功创建提醒。
5. 设置提醒后重启手机，提醒仍按时触发。
6. Android 13+ 首次启动正确引导通知权限与精确闹钟权限。
